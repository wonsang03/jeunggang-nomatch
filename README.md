# 증강노맞

스타크래프트 유즈맵 **노래맞추기**를 웹에서 실시간 멀티플레이로 구현하고, 롤토체스처럼 **증강(Augment)** 을 고르며 진행하는 프로젝트입니다.

사용자가 홈페이지에 접속 → 로그인 → 방 입장 → 같은 방 사람들과 함께 노래를 맞히고, N문제마다 증강을 선택하는 흐름을 목표로 합니다.

---

## 핵심 목표

- 웹에서 여러 명이 **같은 방**에 모여 실시간으로 노래맞추기
- **사이트 관리자(본인)**가 미리 등록한 노래 은행을 기반으로, **방장 설정**만큼 랜덤 출제
- 유튜브 링크로 구간을 **오디오만** 자동 재생 (영상 화면은 노출하지 않음)
- 게임 UI는 마피아42처럼 **카카오톡형 채팅** 중심 (대화문이 메인)
- 슬롯당 +1점, 문제당 40초, 스킵(과반)·완료·타임아웃 시 3초 확인 후 다음
- **20문제마다** 증강 선택(후보 3·리롤 1·20초) → 보관 후 **사용**으로 발동
- 증강 데이터는 `server/prisma/seed.ts`가 원본 (효과 상세는 [증강.md](증강.md))
- 플레이어별 **개별 볼륨** 조절
- 정답 판정·라운드 진행은 **서버 권한**으로 처리해 공정성과 속도 확보
- 다른 사람도 URL로 접속할 수 있도록 **웹 배포**

---

## 유저 플로우

1. 홈페이지 접속
2. 계정 로그인 (또는 회원가입)
3. 로비에서 방 생성 / 방 입장 (공개·비공개)
4. 방장이 장르별 출제 수 등 설정 → 전원 준비 → **방장만** 게임 시작
5. 문제가 시작되면 **노래만 자동 재생** (영상은 안 보임, 문제당 40초)
6. 카톡형 채팅으로 대화하면서, 슬롯별 정답 또는 **스킵** 제출
7. 슬롯을 맞히면 해당 정답 공개 + 맞힌 사람 **+1** → 전부 맞히면 3초 확인 후 다음
8. **20문제마다** 증강 선택 (후보 3, 리롤 1회, 20초) → 보관 후 **사용 버튼**으로 발동
9. 게임 종료 후 결과 확인 → **대기실로** 돌아가 다시 시작하거나, **로비로** 나가기

## 확정 규칙

### 점수

- 한 문제에 맞춰야 할 항목(슬롯)이 N개면, **슬롯당 +1점**
- 예: 정답 슬롯 3개 → 최대 3점 (각각 1점)
- 제목을 맞히면 제목 공개 + 맞힌 사람 **+1**
- 같은 문제에 가수도 있으면, 가수를 맞혀도 별도로 **+1** (제목과 독립)
- **히든 슬롯**은 **+3** (평소엔 안 보이고, 맞히거나 공개될 때 드러남)
- 슬롯마다 다른 사람이 맞춰도 됨 / **한 사람이 여러 슬롯을 연속으로 맞춰도 됨**
- 정답 제출은 **횟수 제한 없음** (틀려도 계속 제출 가능)

### 정답 판정

- 대소문자·띄어쓰기·일부 문장부호 차이는 자동 인정 · 슬롯별 **인정 답안** 추가 가능
- 한 칸에 두 명 이상 적힌 가수(`A & B`, `A · B` 등)는 **사람별로** 나눠 한 명만 맞혀도 인정
  - 괄호 속 유닛명·이름 안의 `and` 는 나누지 않음
- 제목 뒤에 붙는 **속편 번호·부제**는 붙여도, 빼도 인정

### 라운드 진행 (문제당)

| 항목 | 규칙 |
|------|------|
| 제한 시간 | **40초** |
| 시간제 힌트 | **20초 남음** → 가수 **초성**을 ??? 자리에 표시 / **10초 남음** → 제목 **초성**을 ??? 자리에 표시 |
| 증강 힌트 | 우측 **증강 힌트** 칸 — 증강 효과로만 표시 (시간제 초성과 별개) |
| 증강 보유 | 동시에 **1개**만 보관·사용 / 사용 목록 버튼으로 확인 |
| 정답 확인 | 해당 문제의 **모든 슬롯**이 맞춰지면, 노래 약 **3초** 더 들려준 뒤 다음 문제 |
| 슬롯 맞춤 시 | 맞춘 슬롯의 정답만 즉시 공개 + 점수 반영 (나머지는 계속 맞춤) |
| 스킵 | 유저가 **스킵** 제출 → **과반수 이상** 스킵이면 전체 정답 공개 → **3초** 후 다음 문제 |
| 시간 종료 | 40초가 끝나면 남은 정답 공개 → **3초** 후 다음 문제 |

### 출제

- 문제 저장소(은행)에 관리자가 등록한 장르별 풀이 있음
- **방장이** 장르별로 “몇 곡 뽑을지” 설정 (일반전: 한국/일본/해외/애니/버튜버/게임 · **기타는 야차룰 전용**)
- 게임 시작 시 그 설정값 기준으로 은행에서 **랜덤 추출** (방 **최근곡 중복 방지** ON이면 최근에 나온 곡일수록 덜 뽑힘)
- 같은 판에서 동일 곡 중복 출제 없음

```
[문제 은행]
  장르A 100곡 / 장르B 100곡 / ...
        ↓ 방장 설정 예: A=10, B=5, C=10
[이번 판]
  해당 장르 풀에서 랜덤으로 뽑아 진행
```

### 증강

| 항목 | 규칙 |
|------|------|
| 주기 | **20문제마다** 1회 |
| 후보 | 롤토처럼 **3개** |
| 리롤 | 후보 전체 **1회** 무료 리롤 |
| 선택 시간 | **20초** |
| 미선택 | 20초 내 미선택 시 후보 3개 중 **랜덤** |
| 등급 | `bronze` / `silver` / `gold` + `prism`(화면 표기 **프리즘**) |
| 등급 추첨 | 페이즈마다 브론즈·실버·골드 중 **하나**만 등장 (1:1:1) · **프리즘**은 일반 후보에 안 나오고 **프리즘 선택**으로만 |
| 후보 배분 | 방 안에서 **서로 겹치지 않게** 나눠줌 (받는 순서는 매 페이즈 섞음) · 인원×3이 등급 풀보다 크면 그만큼은 겹침 |
| 보유 | 고른 뒤 **바로 효과 적용이 아님** → 인벤에 보관, 유저가 **사용** 버튼으로 발동 |
| 교체(임시) | 다음 증강 선택 시점에 **미사용 보관 증강이 있으면 사라짐** (증강 설계 때 조정 예정) |
| 효과 | 증강마다 `effectType` + `effectValue` (전체 목록은 [증강.md](증강.md)) |

```
문제 1~20 → 증강 선택(보관) → (원하면 사용) → 문제 21~40 → 증강 선택…
```

### 방

| 항목 | 규칙 |
|------|------|
| 최대 인원 | 기본 **10명** (2~10, 방장이 설정) |
| 비공개 방 | 로비 목록에 **안 뜸** · **초대 코드**로만 입장 (방 ID만으로는 불가) |
| 관전 | 플레이어 정원과 **별도**로 최대 **4명** · 대기실에서 플레이어↔관전 전환 · 관전은 **채팅만** |
| 게임 시작 | **방장만** 가능 |
| 게임 모드 | **노래맞추기**(기본) / **리딩방** — 대기실에서 선택 |
| 채팅 색 | 방 안에서 **겹치지 않게** 서버가 막음 · 이미 쓰인 색은 고를 수 없음 |

### UI / 재생

| 항목 | 규칙 |
|------|------|
| 영상 | **유튜브 영상 화면은 보여주지 않음** (썸네일·영상으로 정답 유추 방지) |
| 오디오 | 라운드 시작 시 **노래(해당 구간)만 자동 재생** |
| 메인 화면 | **마피아42 / 카카오톡형 채팅** — 사람들이 치면 대화문만 보임 |
| 볼륨 | 플레이어 각자 조절 |
| 시스템 메시지 | 정답 공개, 점수, 스킵, 라운드 전환 등은 채팅/상단에 안내 |

```
[게임 화면]
  ┌─────────────────────┐
  │  점수 / 타이머 / 슬롯 │
  ├─────────────────────┤
  │  채팅 (대화문)        │  ← 메인
  │  A: ㅋㅋ 뭐지         │
  │  B: 이거 그거 아님?   │
  │  시스템: 제목 정답!   │
  ├─────────────────────┤
  │  입력창 (채팅/정답)   │
  └─────────────────────┘
  + 백그라운드에서 노래 자동 재생 (영상 숨김)
```

## 주요 기능

### 1. 계정 / 로비 / 방

- 회원가입 / 로그인
- 방 생성, 입장, 퇴장 (공개 / 비공개)
- 방 인원 목록, 준비 상태
- 방장: 장르별 출제 수, **최근곡 중복 방지**, 최대 인원 등 설정 + **시작 버튼**
  - 일반 출제 장르: 한국/일본/해외/애니/버튜버/게임 (**기타 제외**)
  - **기타**는 야차룰 전용 · 관리자 문제은행에만 등록
  - 최근곡 중복 방지(기본 ON): 같은 방에서 최근에 나온 곡의 뽑기 가중치를 낮춤 (방금 나온 곡은 안 나온 곡의 1/50)
    - 후보에서 빼는 게 아니라 가중치라서 은행이 작은 장르(게임·버튜버)에서도 안 깨짐
    - 기억 기간은 장르마다 "은행 한 바퀴 도는 판 수"로 자동 조절 (게임 20곡/은행 59 → 3판)
    - 곡이 큐에 담길 때가 아니라 **실제로 틀 때** 기록 (중간에 접은 판의 안 튼 곡은 안 눌림)
- 방 안에서는 **문제 등록 없음** (플레이만)

### 2. 문제 등록 (사이트 관리자 전용)

일반 유저/방장이 아니라, **관리자(서비스 운영자)만** 노래 문제를 등록·관리합니다.

- **유튜브 링크** 입력
- **시작 시간 / 종료 시간** 입력 → 해당 구간만 재생
- **장르별**로 문제 은행(풀)에 저장
- **문제마다** “무엇을 맞춰야 하는지”(슬롯)를 개별 설정

#### 정답 유형 (문제 단위 설정)

한 노래(한 문제)에 대해 맞춰야 할 항목을 문제마다 다르게 둘 수 있습니다.

| 정답 모드 예시 | 플레이어가 맞춰야 하는 것 |
|----------------|---------------------------|
| `title_artist` | 노래 제목 **+** 가수 (슬롯 2개 → 각 +1) |
| `title_only` | 노래 제목만 (슬롯 1개 → +1) |
| `artist_only` | 가수만 (필요 시) |
| `custom` | 관리자가 정의한 답안 슬롯 N개 (각 +1) |

`custom`일 때는 그 문제에 **맞춰야 할 항목을 N개** 두고, 항목마다 정답·인정 답안을 설정합니다.  
인정 답안(다른 표기)은 슬롯별로 등록 가능.

예시 필드:

| 필드 | 설명 |
|------|------|
| youtubeUrl | 유튜브 영상 URL |
| startSec | 구간 시작(초) |
| endSec | 구간 종료(초) |
| genre | 장르 |
| answerMode | 정답 모드 (`title_artist` / `title_only` / `custom` 등) |
| answerSlots | 맞춰야 할 항목 목록 (슬롯 N개, 슬롯당 1점) |
| answerSlots[].label | 항목 이름 (예: 제목, 가수) |
| answerSlots[].answer | 정답 |
| answerSlots[].acceptAnswers | 인정 답안 목록 (선택) |

등록 예시:

```
문제 A: answerMode = title_artist
  → 슬롯: [제목, 가수]  → 최대 2점

문제 B: answerMode = title_only
  → 슬롯: [제목]  → 최대 1점

문제 C: answerMode = custom, 슬롯 3개
  → 슬롯: [제목, 가수, 추가키워드]  → 최대 3점
```

### 3. 문제 출제 방식

관리자가 문제 은행에 쌓아 둔 **장르별 풀**에서, **방장 설정값**만큼 서버가 랜덤 추출합니다.

```
[관리자 → 문제 은행]
  장르A 100곡 / 장르B 100곡 / 장르C 100곡
        ↓ 방장 설정: A=10, B=10, C=10 (값은 방장이 지정)
[이번 판 세트]
  각 장르 풀에서 설정 수만큼 랜덤 추출 후 진행
```

- 같은 판 안에서는 중복 출제 방지

### 4. 게임플레이

- 서버가 라운드 시작 시각·문제 ID·슬롯 구성(정답 제외)을 브로드캐스트
- 클라이언트는 해당 유튜브 구간 재생 (40초)
- 플레이어는 슬롯별 정답 제출 또는 **스킵**
- **서버만** 채점: 슬롯 맞춤 → +1, 해당 정답 공개
- 전 슬롯 완료 / 과반 스킵 / 시간 종료 → 3초 확인 → 다음
- 사용 중인 증강 효과는 서버 채점·진행에 반영

### 5. 증강 시스템 (롤토체스식)

```
문제 1~20  →  증강 선택(보관)  →  문제 21~40  →  증강 선택  →  ...
```

- 후보 **3개**, 전체 리롤 **1회**, 선택 **20초**, 미선택 시 랜덤
- 선택 = 보관. **사용 버튼**을 눌러야 효과 발동
- (임시) 다음 증강 페이즈 때 미사용 보관 증강은 소멸 — 증강 밸런스 작업 때 재조정
- 증강 원본은 `server/prisma/seed.ts` (효과 상세는 [증강.md](증강.md))

증강 예시 필드:

| 필드 | 설명 |
|------|------|
| name | 증강 이름 |
| description | 설명 문구 |
| tier | 등급 (`bronze` / `silver` / `gold` / `prism`) |
| effectType | 효과 종류 (`score_mult`, `peck_song`, … — [증강.md](증강.md)) |
| effectValue | 효과 수치/파라미터 |
| enabled | 사용 여부 |

### 6. UI / 오디오 UX

- 게임 중 화면의 중심은 **카카오톡형 채팅** (마피아42 느낌)
- 유튜브는 **숨긴 플레이어**로 구간만 재생 → 사용자는 **노래만** 들음
- 라운드 시작 시 **자동 재생** (서버 `startAt` 기준 동기화)
- 플레이어마다 **개별 볼륨** 설정
- 일반 대화와 정답 제출은 입력 UX로 구분 (예: 채팅 / 정답 모드, 또는 서버가 정답 후보로 먼저 판정)

## 기술 스택

### 프론트엔드 (`web/`)

- **Vite 6 + React 19 + TypeScript**
- **Tailwind CSS 4** (`@tailwindcss/vite`)
- `socket.io-client` — 실시간 방·게임 이벤트
- 마피아42식 채팅 UI, 개인 볼륨 컨트롤
- 유튜브 **숨김 재생** (YouTube IFrame API · 영상 미노출)

### 백엔드 (`server/`)

- **Node 20+ · Express 4 · Socket.IO 4 · TypeScript**
- **zod** — 소켓 페이로드 검증
- `bcryptjs` + `jsonwebtoken` — 인증
- REST API는 인증(`routes/auth.ts`)·문제은행(`routes/questions.ts`)만, 게임 진행은 전부 소켓

### 데이터

- **Prisma 6 + SQLite** (`server/prisma/dev.db`) — 계정, 문제(장르별), 증강, 전적
- 스키마는 `server/prisma/schema.prisma` · 증강 원본은 `server/prisma/seed.ts`
- 배포 시에도 SQLite 파일을 그대로 올림 (PostgreSQL로 바꾸려면 `datasource db.provider` 교체)

### 배포

- **AWS Lightsail** + **PM2** + **nginx**(WebSocket 리버스 프록시)
- 절차는 [배포/아마존-서버-배포.md](배포/아마존-서버-배포.md) 참고

## 실시간 설계 원칙

- 정답 판정, 라운드 타이머, 점수 계산은 **서버가 단일 권한**
- 클라이언트 시계는 참고용, 판정 기준으로 쓰지 않음
- 같은 방 이벤트는 room 단위 broadcast
- 지연이 중요한 구간: `정답 제출 → 서버 판정 → 전원 반영`

## 도메인 모델

DB에 저장되는 것 (`server/prisma/schema.prisma`):

```
User             계정 (관리자 여부 · 프로필)
Genre            장르
Question         문제 (유튜브 링크 · 구간 · 장르 · 태그)
AnswerSlot       문제별 맞춰야 할 항목 (제목/가수/커스텀 N개 · 히든 여부)
Augment          증강 (이름 · 등급 · effectType/effectValue · 사진)
GameRecord       한 판의 결과
GameRecordEntry  그 판의 플레이어별 점수·순위 (전적/프로필 통계)
```

방·라운드·보유 증강·버프는 DB가 아니라 **서버 메모리**(`src/gameTypes.ts` 의 `Room` / `Member` / `ActiveBuff`)에만 있습니다.

## 로컬 실행 (백엔드 + 프론트)

터미널 2개:

처음 한 번 `server/.env` 를 만듭니다 (`server/.env.example` 복사).
**`JWT_SECRET` 이 비어 있거나 32자 미만이면 서버가 뜨지 않습니다.**

```bash
cd server
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"   # → .env 의 JWT_SECRET 에 붙여넣기
```

```bash
# 1) API + Socket.IO (포트 4000)
cd server
npm install
npx prisma db push
SEED_DEFAULT_ACCOUNTS=1 npm run db:seed   # 로컬 전용 기본 계정까지 만들기
npm run dev

# 2) 프론트
cd web
npm install
npm run dev
```

- 프론트: Vite가 띄운 주소 (예: `http://localhost:5173` ~ `5175`)
- 시드는 기본적으로 **계정을 만들지 않습니다**
  - `SEED_DEFAULT_ACCOUNTS=1` → 로컬 전용 `test` / `test1234`, `admin` / `admin1234`
  - `SEED_ADMIN_PASSWORD=...` → 그 비밀번호로 `admin` 만 생성 (운영은 이쪽)
- 로그인 → 방 만들기 → 게임 시작 → 채팅에 정답 제출 (`밤편지`, `아이유` 등)
- 관리자(`admin`)로 로그인하면 로비 **문제 은행**에서 노래를 등록할 수 있습니다
  - 장르(일반 출제): **한국노래, 일본노래, 해외노래, 애니, 버튜버, 게임**
  - **기타**: 야차룰 전용 풀 (일반전에 안 나옴)
  - 1000곡 이상은 문제 은행 **JSON 대량 등록** 사용
  - 제목 표기가 여러 개면 **인정 답안**에 쉼표로 넣기 (공백/문장부호 차이는 자동 인정)

실제 플로우는 로그인부터 소켓으로 동작합니다.

**소켓 이벤트를 추가할 때는** `socketSchemas.ts` 에 스키마를 먼저 만들고
`on(event, schema, RATE.xxx, handler)` 로 등록하세요. `socket.on` 을 직접 쓰면
검증·레이트리밋·예외 격리가 모두 빠집니다 (핸들러에서 예외가 나면 서버가 죽습니다).

### 안정성 동작

- **재접속 유예 90초** — 게임 중 연결이 끊겨도 점수·증강을 들고 자리를 지킵니다.
  돌아오면 진행 중인 라운드(남은 시간·공개된 슬롯 포함)를 다시 받습니다.
- **재생 불가 곡 자동 스킵** — 임베드 차단·삭제된 영상을 과반이 보고하면 라운드를 넘기고,
  서버 로그에 문제 id와 URL을 남깁니다 (`[question:unplayable]`).
- **서버 시각 동기화** — NTP식 4-타임스탬프로 서버 처리시간을 지연에서 분리합니다.
  재접속·탭 복귀 시 즉시 재동기화합니다.

## 증강 데이터 반영

증강은 `server/prisma/seed.ts`가 원본입니다. 문제은행을 건드리지 않고 증강만 DB에 반영하려면:

```bash
cd server
node scripts/sync-augment-meta.mjs   # seed의 증강을 DB에 upsert · seed에 없으면 enabled=false
```

- 증강은 **이름 + 등급**으로 구분합니다. 등급을 바꾸면 **다른 행**이 되고, 옛 행은 지워지지 않고 꺼집니다.
